# Exam architecture and assessment blueprinting
Start from user-provided assessment scheme: sections, permitted question types, individual marks, selection counts, internal-choice pairs, weightings, duration and scope. Do not assume a fixed marks total, question count, section labeling, Bloom distribution, difficulty curve or learning-outcome codes. Build a blueprint mapping each assessed item to the syllabus scope, intended outcome, cognitive level where specified, marks and difficulty. When choice exists, calculate *candidate-facing attainable marks* rather than summing all printed question marks. Verify all valid choice paths produce the intended assessment total; where path marks or covered units diverge, flag it. For equivalent sets use comparable scope, outcomes, format, marks, complexity and available time; do not recycle trivially changed numbers or claim statistical equating without data. Prefer original, clear, unambiguous questions and consistent terminology. Internal options and 'answer any N' are different operations; represent them explicitly. Audit with `audit_assessment.py` if structured inventory is available.
